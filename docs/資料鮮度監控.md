# 資料鮮度監控表（Google Sheet）

> 建立：2026-07-24 · 解決痛點：首頁只看得到 2 行更新日期，看不出今天十幾個資料集「哪些還沒到齊」。

## 架構（獨立 poller，被動偵測）

```
Supabase snapshots/meta.json (208B)  ─┐
Supabase snapshots/holiday-status.json ├─→ scripts/freshness-log.mjs ─→ (POST) n8n webhook ─→ Google Sheets 節點 upsert
Supabase snapshots/market.json (延伸欄) ┘        │
                                                └─ 純計算：目標交易日 + 各資料集 ✅/⬜/⚠️
```

- **為什麼被動偵測**：只讀「最終落地」的 snapshots，資料真的進 DB 才算 ✅；不管來源是 TWSE/TPEX/FinMind/n8n，判斷一致。未來新增資料集只改 `DATASETS` 一處。
- **為什麼讀 meta.json**：208 bytes，含 5 個核心資料集日期戳（`indexDate/chipsDate/marginDate/stocksDate/sectorDate`）+ `updatedAt/stockCount/sectorHistoryLen`。延伸欄（市場訊號、AI 總結）才需 market.json。

## 狀態判定

- **目標交易日**：今日若為交易日（holiday-status）→ 今日；否則取各資料集最新日（假日/盤前不誤報）。
- 每個資料集：`date >= 目標日` → **✅ READY**；落後 1 天 → **⬜ PENDING（待更新，盤中正常）**；落後 ≥2 天 → **⚠️ DELAYED（告警）**；欄未接 → **— N/A**。

## Google Sheet 版面（矩陣：列=日期，欄=資料集）

分頁 `更新狀態`：

| 日期 | 大盤K線 | 三大法人/期貨/VIX | 融資餘額 | 個股(價/外資/PE) | 板塊T86 | 市場訊號 | AI每日總結 | 檢查時間 |
|:--|:--|:--|:--|:--|:--|:--|:--|:--|
| 2026-07-24 | ⬜ | ⬜ | ⬜ | ⬜ | ⬜ | ⬜ | ⬜ | 12:51 |
| 2026-07-23 | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ | 23:31 |

- **列 key = 目標交易日**；poller 每次執行 upsert 該列（同日多次執行覆蓋，時間戳取最後一次）。
- **條件式格式**：⬜ 黃底、⚠️ 紅底、✅ 綠底。
- 頂部凍結列可放 summary（各欄最新資料日 + 落後天數）— v2。

## n8n 接線（poller 每小時）

1. **Schedule Trigger**：每小時（建議 09:00–24:00 台北，盤後密一點）。
2. **Execute Command / HTTP**：跑 `node scripts/freshness-log.mjs`（帶 `FRESHNESS_SHEET_WEBHOOK` 指向本 workflow 的 Webhook），或直接在 n8n 內用 HTTP Request 讀 meta.json 複刻邏輯。
3. **Google Sheets 節點**：Operation = *Append or Update Row*，Matching Column = `日期`，寫入 `cells` 展開後的各欄。n8n 已有 Google 憑證（stock-chips-daily 在用）。

> 也可改掛在現有 GitHub Actions cron（Supabase/secrets 已就緒），用 Google 服務帳號寫 Sheet — 二選一，見專案待辦。
